# Database — Alembic Migrations

Alembic is the source of truth for schema evolution. SQLAlchemy models live in
`server/app/models/`; migrations live here in `database/alembic/versions/`.

## Setup

From `database/`, using the server's virtualenv (it has `alembic`, `sqlalchemy`,
`psycopg2`, and the app package needed to import models):

```
../server/.venv/Scripts/python -m alembic -c alembic.ini upgrade head
```

## Creating a new migration

```
../server/.venv/Scripts/python -m alembic -c alembic.ini revision --autogenerate -m "describe change"
```

Always review autogenerated migrations before applying. Historical migrations
must never be edited after they have been applied — add a new migration instead.

## Notes

- Migrations run over a sync driver (`psycopg2`); the application itself uses
  `asyncpg` at runtime. `env.py` rewrites the URL automatically.
- The first migration enables the `vector` extension (pgvector) before any
  domain tables are created.
- Vector columns (`challenges.embedding`, `clusters.embedding`,
  `organizations.embedding`) get HNSW indexes with `vector_cosine_ops`.
